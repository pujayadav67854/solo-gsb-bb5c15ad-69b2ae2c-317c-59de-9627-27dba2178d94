# 走位轨迹碰撞排练台

为 2～8 名表演者设计走位的 Web 排练工具。为每人设置**身体半径**，在时间轴上编辑带时刻的
**二维走位点**（关键帧）；每个关键帧还可设置**可选安全半径**，用于表现开伞、展开道具等
占用范围变化（未设置时继承表演者当前半径，相邻关键帧间与位置同步线性插值）。系统在
**分段直线运动**模型下用**解析方法连续计算任意两人的碰撞时间区间——不使用任何离散帧
抽样近似**（半径和随时间变化时退化为一般二次不等式，同样精确求解）。对每一对还连续求出
**最小安全余量** `distance(t) − (rA+rB)` 的全局最小值及发生时刻（凸函数解析求极值，
同样不采样），逐对结果按余量由小到大排列，点击余量时刻即可跳转播放头。舞台还可放置
**轴对齐禁入矩形（obstacles）**：把表演者按实时安全半径视为圆，对每条分段线性轨迹连续
求其与矩形**膨胀边界**（内部 / 四边带状区 / 四角象限共 3×3 个投影区）的进入、离开区间，
按首次进入排序，点击结果跳到进入时刻。每位表演者还可编排**入场口令（entry cues）**：
增删并排序若干矩形入口，逐项设置入口坐标 / 尺寸与**允许进入时窗**；系统按**圆心轨迹**
从矩形外严格进入矩形**内部**的时刻核对口令（起点已在矩形内按 0 秒进入，贴边/仅到角点
不计），在分段直线轨迹上求出全部进入时刻，按口令顺序选取时窗内严格递增、且不与前项共用
同一次停留的触发；未完成项分别标记**错过时窗**或**前序未完成**，已触发结果可点击跳转
播放头。场景还可配置若干**道具交接（handoffs）**：选择两名表演者、轴对齐交接区、
**最大圆心触达距离**与**最短持续秒数 d>0**，系统连续求两人**圆心同时严格位于交接区
内部**且**间距不超过触达距离**的时间区间（跨关键帧相接自动合并，端点取进入/离开的
极限时刻，贴边停留与仅瞬时触达不计），每段 [a,b] 在 b−a≥d 时给出**起始时窗 [a, b−d]**，
点击时窗即跳转播放头。舞台还可配置若干**区域限员（capacity zones）**：增删轴对齐矩形并
编辑坐标、**非负宽高**与**正整数人数上限 limit**；系统沿分段直线走位连续求每个矩形中
**圆心严格位于内部**的在册人数——贴边、瞬时触角与零宽高区域不计，跨关键帧的连续停留
合并、同一人同次停留只计一次，同一时刻的进入/离开一并处理（不产生零长度超员段）；
人数超过上限时按**区间 · 人数 · 人员名单**列出超员时间段（名单变化即分段），并给出
**全程峰值人数**（只计有正持续时间的状态），点击区间起点即跳转播放头。三类风险（碰撞、
禁入区侵入、区域超员）还会合成为侧栏的**风险叠加时间轴**：复用上述分析区间，按时间
切成**互不重叠的风险段**——同刻开始与结束统一结算、舍弃零长度段、生效风险来源或涉及
人员变化即分段，每段列出来源（类型/对象/来源内人员）与涉及人员并集，点击段首即跳转
播放头，编辑走位或区域后实时刷新。Canvas 画布可全程播放，危险区间内当事人高亮，并
给出**首次碰撞时刻**、**全局最小间距**与**最小安全余量**。拖动任意走位点、禁入矩形或
修改半径立即重算。右侧还提供**方案快照**：把当前场景（含入场口令、道具交接与区域限员
配置）存为
命名快照（最多 8 个、localStorage
持久化、可删除/同名覆盖/载入），任选两个快照（或当前场景）在统一时刻轴上对比同名表演者
关键帧线性插值后的**最大位置偏移及发生时刻**，以及碰撞对与禁入区间的**新增、消失与时间
变化**，点击任一结果时刻即跳转播放头；编辑场景后对比立即刷新。内置一组路径十字交叉 / 错峰 / 跟进贴近 / 到位展开道具、且中央放置一个
禁入矩形的样例，并为甲/乙附带**触发 / 错过时窗 / 前序未完成**三态的入场口令样例，
三项甲×乙中央**道具交接**样例（触达 80、最短持续 0.5 s，可交接区间约 [5.18, 6.82]、
起始时窗约 [5.18, 6.32]），以及一个中央**区域限员**样例（上限 1 人，约 [5.18, 6.82]
超员、峰值 2 人）。右侧还提供**滚动窗口奔波负荷**分析：设置窗口时长 W（0<W≤总时长）
与路程上限 D（D≥0），窗口起点在全程连续滑动，按关键帧时刻及其前移 W 秒形成的断点
精确求每人每个完整 W 秒窗口的实际行进路程（首尾停驻不计），列出路程**严格超过 D**
的窗口起点范围、每段最大路程及最早起点，并给全程最大路程；恰等于 D 不违规，相接段
合并，W＝总时长时只检查起点 0。内置样例以 W=4 s、D=500 演示（甲/乙匀速不超限、
丙折线存在约 0–4.93 s 的超限起点范围）。

## 一条命令启动（Docker Compose）

无需预装 Node：克隆仓库后在仓库根目录执行单条命令即可完成依赖安装、镜像构建与启动：

```bash
docker compose up -d --build
```

启动后用浏览器打开：

- **Web 界面：http://localhost:3000**
- **HTTP API：`POST http://localhost:3000/api/analyze`**；样例 `GET http://localhost:3000/api/sample`，健康检查 `GET http://localhost:3000/healthz`

依赖安装（`npm ci --omit=dev`）与初始化全部在镜像构建阶段自动完成，容器启动即直接
运行服务；Web 页面与 HTTP API 同在 **3000** 端口。

停止与清理：

```bash
docker compose down          # 停止
docker compose down --rmi local   # 停止并删除镜像
```

## 不用 Docker（本地 Node 直接运行）

要求 Node.js ≥ 18。

```bash
npm install        # 仅依赖 express
npm start
# 访问 http://localhost:3000
```

## 使用说明

- **选中表演者**：点击右侧列表；新增走位点都会加到当前选中者。
- **移动走位点**：在画布上直接拖动彩色圆点（位置变化），或在底部时间轴拖动对应泳道的圆点（改时刻）。**松手前实时重算**。
- **新增走位点**：选中某人后，在空白处单击（或双击）即可在**当前播放时刻**加入关键帧。
- **删除走位点**：右键画布圆点，或选中圆点后按 `Delete`（每人保留至少 1 个点）。
- **关键帧安全半径**：选中任意圆点后，画布下方出现编辑条，可填写该帧安全半径（0～150 世界单位，留空继承表演者当前半径）。半径与位置在相邻关键帧间**同步线性插值**，首尾之外保持端点值；画布上选中者各帧会画出占用范围盘（实线＝自定义，虚线＝继承），播放时身体盘实时张开/收拢，时间轴上自定义半径的时刻柄有白圈标记。修改/拖动后立即刷新碰撞区间。
- **增减表演者**：右侧"＋增加 / ✕"，人数限制 2～8；半径范围 0～150 世界单位。
- **禁入矩形**：点顶部"**＋ 禁入区**"后，在画布上**拖出**一个轴对齐矩形（单击空白则投放
  默认尺寸，`Esc` 取消）；可直接**拖动矩形移位**（边界自动钳在画布内），选中后画布下方
  出现编辑条，可改名称 / 宽 / 高；**右键矩形**或选中后按 `Delete` 删除。
- **播放**：`▶ 播放`（或空格键），支持 0.25× / 1× / 2× / 4×；点击时间轴任意位置可跳转时刻。
- **红色高亮**：当前时刻处于碰撞区间的当事人，身体描边变红、显示红色半径盘，并用红色虚线连接冲突双方、标注实时间距与当前半径和。
- **禁入区高亮**：当前时刻被侵入的矩形填充变红并列出侵入者，当事人身体盘同样红色高亮，
  时间轴对应泳道叠加琥珀色侵入条。
- 右侧"逐对结果"按**最小安全余量由小到大**列出每一对：精确碰撞区间（可有多段，已自动合并跨关键帧的相邻区间）、首碰时刻、**最小安全余量 `distance − 半径和` 及其发生时刻**、最小间距与该对**半径和的变化范围**。**点击余量时刻（蓝色下划线）可将播放头跳转到该时刻并刷新画布**；摘要区的"最小安全余量"一行同样可点击跳转。余量 ≤ 0 即存在碰撞。
- 右侧"**禁入区侵入**"面板为每位表演者 × 每个矩形列出连续侵入区间（已合并跨关键帧的
  相邻区间），**按首次进入时刻升序**，无侵入者排在后面；**点击任意侵入结果或时间轴琥珀
  色条即跳到该区间的进入时刻**，播放过程中正在侵入的行实时高亮。
- **入场口令**：右侧"**入场口令**"面板随当前选中表演者切换，用"**＋ 新入口**"在该表演者
  当前圆心处投放入口矩形，可**逐项编辑 x / y / 宽 / 高与允许进入时窗（秒）**，用 **↑ / ↓**
  调整执行顺序、**✕** 删除。核对只看**圆心**：从矩形外进入矩形**内部**才算进入，起点已在
  矩形内按 **0 s** 进入，**沿边擦边、仅抵达边界或角点一律不计**（0 宽/高的退化矩形也无法
  进入）；系统在分段直线轨迹上求出**全部进入时刻**（跨关键帧相接的停留合并为一次），再按
  口令顺序贪心匹配——触发时刻必须**严格递增**、落在时窗内（**含端点**），且**同一次停留
  只能计一次**。每行即时显示三种状态：**✓ 已触发**（绿色，附带的时刻可点击跳转播放头）、
  **✕ 错过时窗**（红色，并列出实际进入时刻或"全程未进入"供诊断）、**⛒ 前序未完成**
  （琥珀色，前一口令未触发后连锁挂起）。画布上选中者的入口矩形以状态色虚线框画出，
  左上角带 ①②③ 顺序徽标，已触发口令在实际进入位置画状态色圆点。拖动走位、改半径、改
  入口矩形或时窗后**立即重算**；口令数据随场景一并存入方案快照，载入即恢复。
- **道具交接**：右侧"**道具交接**"面板用"**＋ 新增交接**"添加一项交接（默认取当前选中者
  与下一名表演者，交接区落在两人当前圆心中点），每项可**下拉更换两名表演者**、编辑交接区
  **x / y / 宽 / 高**、**触达距离**（两圆心间距上限）与**最短持续秒数 d**（必须 > 0），
  **✕** 删除。系统沿分段直线轨迹连续求两人**圆心同时严格位于交接区内部**且**间距 ≤ 触达
  距离**的区间（贴边停留与仅瞬时触达不计，跨关键帧相接自动合并，端点即进入/离开的极限
  时刻）；每段 [a,b] 若 b−a ≥ d 即给出**起始时窗 [a, b−d]**（绿色芯片，**点击跳转播放头**
  到时窗起点）。交接区在画布上以**紫色虚线框**画出并标注双方姓名与参数，当前时刻处于可
  交接区间时矩形高亮、双方圆心以紫色虚线相连并标注实时间距。拖动走位、改半径或改交接
  参数后**立即重算**；删除表演者时引用其的交接一并移除；交接配置随场景存入方案快照，
  载入即恢复，`POST /api/analyze` 返回同一结果（见下文 HTTP 接口）。
- **区域限员**：顶部"**＋ 限员区**"在画布上**拖出**一个轴对齐矩形（单击空白投放默认
  尺寸，`Esc` 取消），或右侧"**区域限员**"面板的"**＋ 新增限员区**"在舞台中央投放。
  矩形可直接**拖动移位**（边界自动钳在画布内），**右键矩形**或选中后按 `Delete` 删除；
  选中后画布下方出现青色编辑条，面板中每行也可编辑**名称 / x / y / 宽 / 高 / 人数上限**：
  宽、高为**非负数**（0 宽或 0 高的退化区域没有内部，永不统计并给出提示），人数上限
  **limit 必须为正整数**（非正或小数不会被接受，输入回退为当前有效值）。系统沿分段
  直线走位连续统计每个矩形内**圆心严格位于内部**的人：**贴边停留、仅瞬时触角（穿过
  角点/边界）、零宽高区域一律不计**；跨关键帧相接的连续停留合并，同一人同一次停留
  **只计一次**；**同一时刻的进入与离开一并处理**——同刻一进一出不产生瞬时超员，也不
  生成零长度超员段，开场/收场的单点状态同样不计。人数 **> 上限**时按时间段列出
  **区间 · 人数 · 人员名单**（人数与名单随状态恒定；**名单一变化即另起一段**，即使
  人数不变也分段），并显示**全程峰值人数与峰值名单**（峰值只在有正持续时间的状态中
  取）。每行状态颜色：青色=正常、红色边框=存在超员段、灰色=零宽高退化。画布上限员区
  为**青色虚线框**，当前在册人数实时显示在标签上，**当前超员时矩形变红**并列出在册
  人员、当事人身体盘红色高亮。**点击任一超员区间芯片（其起点）即跳转播放头**；拖动
  走位、修改矩形或人数上限后**立即重算**；限员配置随场景存入方案快照，载入即恢复，
  `POST /api/analyze` 返回同一结果（见下文 HTTP 接口）。
- **风险叠加时间轴**：右侧"**风险叠加时间轴**"面板把**碰撞、禁入区侵入、区域超员**
  三类风险的既有分析区间投影到统一时刻轴，合成为**按时间排序、互不重叠**的风险段。
  每段显示**起止时刻与时长、风险来源**（红色＝碰撞"甲 × 乙"、琥珀色＝禁入侵入"禁入
  区名"、青色＝区域超员"限员区名（N 人）"，逐来源列出该来源涉及人员）与整段的
  **涉及人员**并集（按场景内表演者次序去重）。**同刻开始与结束统一结算**：一进一出
  不在中间产生瞬时状态，**零长度段（碰撞相切点、角点侵入）整体舍弃**；**生效风险来源
  或涉及人员变化立即分段**（即使风险连续、来源不变而仅名单更换也另起一段）。
  **点击任意段（或其时刻）即把播放头跳到该段起点**并刷新画布；播放/拖动播放头时当前
  生效的段实时高亮（同一时刻至多一段）。拖动走位点、修改半径、增删/编辑禁入区或限员
  区后，时间轴随碰撞等结果**实时刷新**；`POST /api/analyze` 在 `riskTimeline` 字段返回
  同一份结果（见下文 HTTP 接口）。
- **奔波负荷（滚动窗口路程）**：右侧"**奔波负荷（滚动窗口路程）**"面板设置**窗口时长 W**
  （0 < W ≤ 总时长，秒）与**路程上限 D**（≥ 0，世界单位）。窗口起点 s 在
  **[0, 总时长−W] 上连续滑动**（不是固定步长采样）：以关键帧时刻及其**前移 W 秒**
  形成的断点把起点轴切成若干区间，区间内窗口路程关于 s 线性，用线性求根**精确**给出
  路程 **F(s) 严格大于 D** 的起点范围，相接范围自动合并。面板逐人列出：**全部窗口
  最大路程及其最早窗口起点**（可点击跳转）、每个**严格超限起点范围** [起, 止]、该范围内
  **最大路程及其最早起点**（均可点击跳转到对应窗口起点），行在有超限时红边标记，播放头
  落入超限起点范围时整行高亮；时间轴对应泳道底部叠加紫色超限范围条（点击跳到范围起点）。
  **首尾停驻不计路程**（静止段速度为 0），**恰等于 D 不违规**；**W 等于总时长时只检查
  起点 0**（提示"仅起点 0 一个窗口"，超限给出 0–0 s 的单点范围）。修改 W / D 或拖动走位、
  关键帧时刻后**立即刷新**；非法输入（W ≤ 0、W > 总时长、D < 0、非数字）在面板内给出
  **清晰错误**并把输入框**回退为当前有效值，不覆盖既有有效设置**；缩短总时长使 W 越界时
  自动把 W 钳为新总时长并提示。参数随**方案快照保存/载入**（旧快照缺省该字段时回退为
  W＝总时长、D＝0，不报错）；`POST /api/analyze` 在 `travel` / `travelResults` 字段返回
  同一份结果（见下文 HTTP 接口）。

## 方案快照（两方案对比）

## 算法：为什么不是帧抽样

每人在相邻关键帧之间是匀速直线运动，**安全半径也在相邻关键帧之间线性变化**；
关键帧之外位置静止、半径保持端点值。对表演者 A、B，在两人活动段
的重叠时间窗 \[lo, hi\] 内，其相对位置与半径和都是时间的一次函数：

\[
\mathbf r(t)=\mathbf p_A(t)-\mathbf p_B(t)=\mathbf u+\mathbf v\,t,\qquad
R(t)=R_A(t)+R_B(t)=c+d\,t
\]

碰撞条件 \(\lVert\mathbf r(t)\rVert \le R(t)\)（两侧均非负，可直接平方）是关于
\(t\) 的一般二次不等式：

\[
\bigl(\lVert\mathbf v\rVert^2-d^2\bigr) t^2 +
2\bigl(\mathbf u\!\cdot\!\mathbf v-cd\bigr) t +
\lVert\mathbf u\rVert^2-c^2 \le 0
\]

用求根公式直接解出区间端点并钳制到重叠窗：首项系数可正（常规，碰撞段在两根之间）、
可负（半径张开速度大于接近速度，碰撞解集向两端开口，钳制后最多两段）、可为零
（线性/恒定退化）。判别式 < 0 时按开口方向判为整段碰撞或全程不碰；相对静止
（\(\lVert\mathbf v\rVert=0\)）情形由同一求解器覆盖——只靠半径张开也能精确解出
进入/脱离时刻。对两人分段活动区间做双指针扫描合并，得到全部精确碰撞区间。
**最小（几何）间距**取相对距离二次函数顶点（钳制在窗内）的全局最小值，与半径
变化无关。相切（距离恰好等于半径和）记为零长度碰撞区间。

**最小安全余量** \(m(t)=\lVert\mathbf r(t)\rVert-R(t)\) 是\(\sqrt{q(t)}\)（凸函数）
减去线性函数，因此在每段内恒为**凸函数**：全局最小只可能出现在段端点，或
\(\lVert\mathbf v\rVert>|d|\) 时唯一的驻点

\[
t^{*}=\frac{-\mathbf u\!\cdot\!\mathbf v+
d\sqrt{\bigl(\lVert\mathbf u\rVert^2\lVert\mathbf v\rVert^2-(\mathbf u\!\cdot\!\mathbf v)^2\bigr)
\big/\bigl(\lVert\mathbf v\rVert^2-d^2\bigr)}}{\lVert\mathbf v\rVert^2}
\]

退化情形由同一公式/分支覆盖：相对静止（\(\lVert\mathbf v\rVert=0\)）或半径变化比
相对运动快（\(\lVert\mathbf v\rVert\le|d|\)）时 \(m\) 单调，最小值在端点；相对轨迹
过原点（\(|\mathbf u\times\mathbf v|=0\)，距离可为零）时驻点即 \(\lVert\mathbf r\rVert=0\)
的尖点。逐段取候选点的最小值即得该对的全局最小余量与发生时刻——同样全程解析，
不做任何时间采样。余量 ≤ 0 与碰撞区间非空互为等价（数值容差内）。

该实现位于 `public/core.js`，浏览器与 Node 同一份代码，零第三方依赖。

### 禁入矩形：圆对轴对齐矩形膨胀边界的连续求交

矩形 \(\mathcal R=[X_0,X_1]\times[Y_0,Y_1]\) 对圆心 \(\mathbf p=(x,y)\) 的最近点距离为

\[
d\bigl(\mathbf p,\mathcal R\bigr)^2 =
\operatorname{clamp}(x-X_0,0,x-X_1)^2 +
\operatorname{clamp}(y-Y_0,0,y-Y_1)^2
\]

（`clamp` 为夹到区间内，内部贡献 0）。侵入条件
\(d(\mathbf p(t),\mathcal R)\le r(t)\) 按圆心所在的 **3×3 区域**（矩形内部、上下左右四条
边外带状区、四个角点象限）分别表现为常数、单坐标二次、双坐标二次。对每段
\(\mathbf p(t)=\mathbf u+\mathbf v\,t\)、\(r(t)=c+d\,t\)，先用四条边界线
\(X_0/X_1/Y_0/Y_1\) 与轨迹的交点把时间窗切成若干子段；每个子段内最近点投影恒为
\(q_x(t)=a_x u_x+b_x v_x t+c_x\)、\(q_y(t)=a_y u_y+b_y v_y t+c_y\)
（\(a,b\in\{0,1\}\)，\(c\in\{-X_1,0,-X_0\}\)），于是

\[
q_x(t)^2+q_y(t)^2 \le (c+d\,t)^2
\]

仍是关于 \(t\) 的一般二次不等式，直接复用双人碰撞的同一求根器精确求解：

- **从矩形内部起步**：首子段距离恒 0，区间自然以 \(t=0\) 为起点；
- **仅角点相切**（轨迹严格从角象限掠过、最近距离恰等于半径）：判别式为零，记为零长度区间；
  沿边外等距线擦边（投影落在边上）则得到一段有限宽度的连续接触；
- **半径随时间变化**：静止张开 / 移动中张收都由同一二次式覆盖（首项系数可正可负可零）；
- **跨关键帧**：各活动段与各子段解出的区间统一做相邻合并，相接区间不重复计数。

全程没有任何离散帧抽样——解出的就是进入、离开的精确时刻。每人 × 每矩形一条结果，
按**首次进入时刻**升序排列。

### 入场口令：圆心对矩形内部的严格进入与顺序匹配

口令核对对象是**圆心轨迹本身**（与身体/安全半径无关）。矩形内部是两个坐标开区间之交：

\[
\mathcal R^\circ=\{(x,y):X_0<x<X_1,\ Y_0<y<Y_1\}
\]

对每段分段直线 \(\mathbf p(t)=\mathbf u+\mathbf v\,t\)，分别求仿射坐标严格落在
\((X_0,X_1)\)、\((Y_0,Y_1)\) 内的时刻区间（常数坐标恰在边界上 = 贴边，整段不计），
两开区间相交即圆心位于矩形内部的时间段；跨关键帧相接的区间经同一 `mergeIntervals`
合并为**一次停留**，每个合并停留段的起点就是一个进入时刻：

- **起点在内**：首个停留段以 \(t=0\) 开始，进入时刻记 0；
- **沿边擦边 / 仅到边界或角点**：开区间无正长度，不产生进入；
- **穿过角点进入内部**：两角坐标同时越过边界，进入时刻即角点时刻；
- **退化矩形**（width=0 或 height=0）没有内部，永远无法触发。

随后按口令数组顺序贪心匹配，第 \(i\) 条口令只在其前序口令**全部已触发**时才参与匹配，
候选进入须同时满足：严格晚于上一条的触发时刻（**严格递增**）、落在时窗
\([t_{lo},t_{hi}]\)（**含端点**）、未被同一矩形前一条口令以同一次停留占用
（**同一次停留只计一次**；不同入口矩形各自独立）。满足条件取最早进入为触发；
否则该项记为**错过时窗（missed）**并使链路断开，其后各项一律记为**前序未完成
（blocked）**。该实现位于 `rectangleEntryTimes` 与 `evaluateCues`，仍是纯解析计算、
零采样、零第三方依赖。

### 道具交接时窗：双人同处交接区且间距受限的连续区间

一项交接由两名表演者（`aId`/`bId`）、轴对齐交接区
\(\mathcal R=[X_0,X_1]\times[Y_0,Y_1]\)、最大圆心触达距离 \(reach\ge 0\) 与最短持续
秒数 \(d>0\) 组成。可交接区间定义为

\[
\{\,t:\ \mathbf p_A(t)\in\mathcal R^\circ,\ \mathbf p_B(t)\in\mathcal R^\circ,\
\lVert\mathbf p_A(t)-\mathbf p_B(t)\rVert\le reach\,\}
\]

即两人**圆心同时严格位于交接区内部**（与入场口令同一开区间判定，**贴边停留不计**）
且**间距不超过触达距离**。求法分三步，全程解析、零采样：

1. **停留区间**：分别对两人求圆心严格位于矩形内部的停留区间（复用入场口令的
   开区间逻辑与 `mergeIntervals` 合并），两列表求交集，得到"同处交接区"的时间窗；
2. **触达切割**：交集窗内两人相对位置仍是分段一次函数
   \(\mathbf r(t)=\mathbf u+\mathbf v\,t\)，条件
   \(\lVert\mathbf u+\mathbf v\,t\rVert^2\le reach^2\) 是首项系数
   \(\lVert\mathbf v\rVert^2\ge 0\) 的二次不等式（解集恒为单区间），按双方关键帧段
   双指针切分后逐段复用 `solveQuadraticLE` 精确求解；
3. **合并与时窗**：全部子区间经 `mergeIntervals` 合并（跨关键帧相接自动并为一段，
   端点即进入/离开的极限时刻），**仅瞬时触达（零长度区间）不计**；每段 \([a,b]\)
   若 \(b-a\ge d\)，给出**起始时窗 \([a,\,b-d]\)**——交接开始时刻落在该时窗内即可
   在区间内完成一次持续 \(d\) 秒的交接。

该实现位于 `normalizeHandoffs` 与 `analyzeHandoff`，与前端、API 共用同一份代码。

### 区域限员：圆心严格在内的事件扫描线

一个限员区由轴对齐矩形
\(\mathcal R=[X_0,X_1]\times[Y_0,Y_1]\)（width/height 非负，0 宽/高没有内部）与正整数
人数上限 \(limit\) 组成。对每位表演者直接复用入场口令的圆心停留区间
`rectangleStayIntervals`——仿射坐标**开区间**解析，贴边、瞬时触角、零宽高区域均不产生
停留，跨关键帧相接的停留已合并，因此同一人同一次停留天然只产生一对事件。

把所有人的停留段汇总为事件流：进入为 \(+1\)、离开为 \(-1\)，按时刻排序后做扫描线：

1. **同刻一并处理**：同一时刻（含跨段解析的浮点同级误差）的全部进出事件先归为一组、
   同时应用在册集合，组与组之间在册名单恒定。于是同刻一进一出（人数不变、名单变化）
   不会产生瞬时状态，开场/收场的单点状态为零持续、自动丢弃，**不生成任何零长度
   超员段**；
2. **正持续成段、名单变化即分段**：相邻事件组之间是一个名单恒定且持续时间为正的
   状态；只保留人数 \(>limit\) 的状态作为超员段，段内记录区间、人数与人员名单
   （按场景内表演者次序），名单一旦变化即另起一段；
3. **全程峰值**：在所有有正持续时间的状态上取在册人数最大值及当时名单（峰值状态的
   开始时刻一并返回），仅瞬时出现的人数不计入。

全程解析、零离散帧抽样；该实现位于 `normalizeCapacityZones` 与 `analyzeCapacityZone`，
与前端、API 共用同一份代码。

### 风险叠加时间轴：三类风险区间的统一事件扫描线

`buildRiskTimeline(analysis, performers, duration)` 不重新做几何计算，只复用三类既有
分析结果的区间端点：

- **碰撞**——`pairs[]` 中 `collision=true` 各对的合并碰撞区间，每段区间的来源为
  "这一对"，涉及人员为该对两人；
- **禁入区侵入**——`obstacleConflicts[]` 中 `conflict=true` 的"表演者 × 禁入区"连续
  侵入区间，来源涉及该表演者一人；
- **区域超员**——`capacityResults[].intervals` 的每个超员状态（扫描线已剔除零长度段、
  名单变化已分段），来源携带该状态的人员名单。

每个**正持续**区间产生一对进入 `(t, +1, source)` / 离开 `(t, −1, source)` 事件；
**零长度区间（相切点/瞬时触角）直接舍弃**——既不成段也不切割其它风险。事件按时刻
排序后做扫描线：

1. **同刻统一结算**：同一时刻（含跨解析的浮点同级误差）的全部开始与结束事件归为一组、
   同时应用到生效来源集合——同刻一进一出不在中间产生瞬时状态，也不产生零长度空窗；
2. **来源或人员变化即分段**：相邻事件组之间，"生效来源集合 + 涉及人员并集"恒定，
   恰好构成一个风险段；任一组事件使来源集合变化（新增/结束一类风险），或来源集合不变
   而其涉及人员并集变化（如限员区超员名单从 {甲,乙} 换成 {甲,丙}），都立即另起一段；
   超员状态本身已按名单分段，统一扫描线无需特判；
3. **只输出正持续、非空风险段**：风险为空的时段不产生段，段按起点严格升序、首尾相接处
   允许同刻相接但互不重叠；段内来源按类型（碰撞→禁入侵入→区域超员）与首次出现次序
   排列，涉及人员按场景内表演者次序去重。

整段合成只在端点事件上做归并，无离散帧抽样；实现位于 `public/core.js` 的
`buildRiskTimeline`，浏览器侧栏与 `POST /api/analyze`（`riskTimeline` 字段）共用同一份。

### 滚动窗口奔波负荷：分段线性窗口路程的断点求根

参数 `{ windowSeconds: W, distanceLimit: D }`（0 < W ≤ 总时长 T、D ≥ 0）。把每位表演者
沿 `buildSegments` 展开为活动段，每段圆心速度大小 \(v_i=\lVert\mathbf v_i\rVert\) 恒定
（首尾停驻段速度为 0，天然不计路程）。窗口 \([s, s+W]\) 在该段上的重叠时长为

\[
o_i(s)=\min(s+W,t_{i+1})-\max(s,t_i)\quad(\text{钳到 }[t_i,t_{i+1}])
\]

窗口实际行进路程为各段贡献之和：

\[
F(s)=\sum_i v_i\,o_i(s),\qquad s\in[0,\,T-W]
\]

每个 \(o_i(s)\) 是关于 s 的分段线性函数，折点只可能出现在窗口左沿越过段端点
（\(t_i\)、\(t_{i+1}\)）或窗口右沿越过段端点（\(t_i-W\)、\(t_{i+1}-W\)）的时刻。
枚举全部折点（含 0 与 T−W，去重并钳入起点域），则 **F(s) 在相邻断点之间斜率恒定**：
线性求根 \(F(s)=D\) 即可精确判定该小区间内 F>D（**严格大于**，数值容差内相等不算）的
部分；各小区间解出的超限范围再经同一 `mergeIntervals` 做**相接段合并**（折点处恰为 D
的两段并为一段），范围在合并后可能横跨多个折点（帐篷形峰值），故范围最大路程在范围
端点与其内部全部折点上取最大、并取最早达到的起点。全程最大路程同理在断点并集上取。
W = T 时起点域退化为单点 {0}，只检查起点 0（超限给出零长度单点范围）。全程无固定步长
采样；实现位于 `public/core.js` 的 `normalizeTravel` / `analyzePerformerTravel` /
`analyzeTravel`，浏览器侧栏与 `POST /api/analyze` 共用同一份。

### 方案快照对比

`compareScenes(sceneA, sceneB)` 在统一时刻轴 `[0, max(dA,dB)]` 上对比两版场景：

- **同名表演者偏移**：两侧关键帧经分段线性插值后的位置差
  \(\Delta(t)=\lVert\mathbf p_1(t)-\mathbf p_2(t)\rVert\) 在每个断点区间内是凸函数，
  全局最大必出现在双方关键帧时刻（含 0 与两侧时长端点，帧外保持末位静止），
  枚举并集断点即得**精确最大偏移与发生时刻**，不做时间采样；
- **碰撞对 / 禁入区间**：分别用 `analyzeScene` 解析两场景，碰撞对按两人名字配对、
  禁入区间按 表演者名 × 矩形名配对；双方的区间列表按最大时间重叠贪心配对
  （零长度相切点也可配），未匹配的新区间记为**新增**、未匹配的旧区间记为**消失**、
  配到但端点超出容差的记为**时间变化**；
- 表演者与禁入区本身的增删单列。

纯数据计算、零第三方依赖，浏览器（快照面板实时对比）与 Node（测试）共用同一份代码。

## HTTP 接口

- `GET /api/sample` — 返回内置样例场景（含关键帧半径 `r`，如丙 t=8 帧 `r: 60` 表现展开道具；
  另含中央禁入矩形 `obstacles`，甲 3 条 / 乙 1 条入场口令 `cues`，以及一项甲×乙中央
  道具交接 `handoffs`，以及一个中央区域限员 `capacityZones`，以及滚动窗口奔波负荷参数
  `travel: { windowSeconds: 4, distanceLimit: 500 }`）
- `POST /api/analyze` — 入参
  `{ "duration": 12, "performers": [{ "name": "甲", "radius": 20, "keys": [{"t":0,"x":60,"y":300}, {"t":8,"x":500,"y":300,"r":60}],
  "cues": [{"x":440,"y":240,"width":120,"height":120,"winStart":4,"winEnd":6}] }],
  "obstacles": [{ "id": "o1", "name": "禁入区", "x": 440, "y": 240, "width": 120, "height": 120 }],
  "handoffs": [{ "aId": "p1", "bId": "p2", "x": 440, "y": 240, "width": 120, "height": 120,
  "reach": 80, "minDuration": 0.5 }],
  "capacityZones": [{ "id": "z1", "name": "中央限员区", "x": 440, "y": 240,
  "width": 120, "height": 120, "limit": 1 }] }`。
  `obstacles` 可整体缺省（旧请求完全兼容）；每项的 `id`、`name` 可缺省（自动补
  `o<随机串>` 与"禁入区 N"），`x/y/width/height` 为数字，尺寸非负（允许 0 宽/高的退化
  矩形）。关键帧可选字段 `r` 为该帧安全半径（非负数；缺省或 `null` 即继承表演者 `radius`）。
  `cues` 为按顺序排列的入场口令数组，可整体缺省；每项形如
  `{id?, x,y,width,height, winStart?, winEnd?}`：`width/height` 非负（0 为永不可触发的
  退化入口），时窗缺省为 `[0,duration]`、端点倒置自动交换、缺省 `id` 自动补 `c<随机串>`。
  `handoffs` 为道具交接数组，可整体缺省；每项形如
  `{id?, aId, bId, x, y, width, height, reach, minDuration}`：`aId`/`bId` 引用表演者的
  `id`（未携带 `id` 的表演者无法被交接引用），`width/height/reach` 非负（0 宽/高的退化
  交接区没有内部，永不满足），`minDuration` 必须为正数，缺省 `id` 自动补 `h<随机串>`。
  `capacityZones` 为区域限员数组，可整体缺省（旧请求完全兼容）；每项形如
  `{id?, name?, x, y, width, height, limit}`：`width/height` 非负（0 宽/高的退化区域
  没有内部，永不统计），`limit` 必须为**正整数**（请求中小数报 400；引擎规整时非正数项
  丢弃），缺省 `id` 自动补 `z<随机串>`、缺省 name 补"限员区 N"。
  `travel` 为滚动窗口奔波负荷参数，**可整体缺省（旧请求完全兼容，返回 `travel: null`）**，
  形如 `{ windowSeconds: W, distanceLimit: D }`：`windowSeconds` 必须为满足
  **0 < W ≤ duration** 的有限数（缺失、非数字、≤0 或超过总时长均报 400 并给出清晰说明），
  `distanceLimit` 必须为**非负有限数**（缺失、非数字或负数报 400）。
  返回每对碰撞区间（含 `radiusSumMin` / `radiusSumMax` 半径和变化范围）、**最小安全余量
  `minMargin` 及发生时刻 `minMarginT`**（`distance(t) − (rA+rB)` 的连续全局最小值），
  `pairs` 按余量由小到大排序；场景级另附 `minMargin` / `minMarginT` / `minMarginPair`、
  首次碰撞时刻与最小间距。禁入矩形方面返回：
  - `obstacles` — 规整后的矩形（顶层与 `scene.obstacles` 各一份）；
  - `obstacleConflicts` — 每位表演者 × 每个矩形一条
    `{ performerId, performerName, obstacleId, obstacleName, intervals, conflict,
    firstEntry, lastExit }`，侵入项按 `firstEntry` 升序、无侵入项随后；
  - `firstObstacleEntry` / `firstObstacleConflict` — 场景级首次侵入时刻与
    `[表演者 id, 矩形 id]`（无侵入为 `null`）。

  入场口令方面返回 `cueResults`：每位携带口令的表演者一条
  `{ performerId, performerName, results: [{ index, cue, status, triggerT, entries }] }`，
  `status` 为 `triggered`（已触发，`triggerT` 为触发时刻）/ `missed`（错过时窗）/
  `blocked`（前序未完成），`entries` 为该入口矩形的全部圆心进入时刻（诊断用）；
  无口令表演者不出现在数组中。

  道具交接方面返回：
  - `handoffs` — 规整后的交接配置（顶层与 `scene.handoffs` 各一份）；
  - `handoffResults` — 每项交接一条
    `{ handoffId, handoff, aId, bId, aName, bName, valid, intervals, windows, feasible }`：
    `intervals` 为两人圆心同时严格位于交接区内部且间距 ≤ `reach` 的连续区间
    （已合并跨关键帧相接段、已剔除零长度的瞬时触达），`windows` 为每段
    `b−a ≥ minDuration` 时给出的起始时窗 `[a, b−d]`，`feasible` 表示存在可用时窗；
    `aId === bId` 或引用的表演者不存在时 `valid: false` 且区间为空。

  区域限员方面返回：
  - `capacityZones` — 规整后的限员配置（顶层与 `scene.capacityZones` 各一份）；
  - `capacityResults` — 每个限员区一条
    `{ zoneId, zoneName, limit, intervals, overcrowded, firstStart, peak, peakT, peakMembers }`：
    `intervals` 为只含圆心严格在内部者、且人数 `count > limit` 的连续时间段，每段形如
    `{ start, end, count, members:[{id,name}] }`（同刻进出一并处理、已剔除零长度段，
    名单变化即分段）；`peak`/`peakT`/`peakMembers` 为全程峰值人数、其状态开始时刻与
    峰值名单（只计有正持续时间的状态；无人进入时 `peak=0`、`peakT=null`）；
    `firstStart` 为首个超员段起点（无超员为 `null`）。

  三类风险合成为风险叠加时间轴 `riskTimeline`：按时间排序、互不重叠的风险段数组，
  每段形如 `{ start, end, sources, members }`；`sources` 为该段同时生效的风险来源，
  每项 `{ type, typeLabel, label, members:[{id,name}] }`，`type` 为
  `collision`（碰撞，`label`＝"甲 × 乙"，成员为该对两人）/ `obstacle`（禁入区侵入，
  `label`＝禁入区名，成员为侵入者一人）/ `capacity`（区域超员，`label`＝"限员区名
  （N 人）"，成员为该超员状态名单），段内来源按碰撞→禁入侵入→区域超员与首次出现
  次序排列；`members` 为整段全部来源涉及人员的并集（去重、按场景内表演者次序）。
  同刻开始与结束已统一结算，零长度区间（相切点/瞬时触角）不出现在结果中，生效来源
  或涉及人员变化处即段边界；无任何风险时为 `[]`。

  滚动窗口奔波负荷方面返回 `travel`（旧请求缺省 `travel` 入参时为 `null`）：
  `{ config:{windowSeconds, distanceLimit}, travelResults, maxDistance, maxStart,
  maxDistancePerformerId, maxDistancePerformerName }`，其中 `travelResults` 按场景内
  表演者次序逐人给出
  `{ performerId, performerName, windowSeconds, distanceLimit, ranges, overloaded,
  maxDistance, maxStart, totalDistance }`：
  - `ranges` 为路程**严格超过** D 的窗口起点范围（相接段已合并），每段形如
    `{ start, end, maxDistance, maxStart }`——`[start,end]` 是超限**窗口起点**的范围
    （对应窗口为 `[start, start+W]`～`[end, end+W]`），`maxDistance/maxStart` 为该范围
    内（含内部折点峰值）的最大窗口路程及其最早窗口起点；W＝总时长且超限时为单点
    `{start:0,end:0,...}`；
  - `overloaded` 为 `ranges` 是否非空；
  - `maxDistance/maxStart` 为**所有完整窗口**（不论是否超限）中的最大路程及其最早起点；
  - `totalDistance` 为起点 0 的窗口路程（W＝总时长时即全程总路程）；
  - 场景级 `maxDistance/maxStart/maxDistancePerformerId/maxDistancePerformerName` 汇总
    全员中的最大窗口路程（无表演者时为 `null`）。

  响应额外携带 `scene`，其中缺省半径已解析为具体数值、矩形已规整、每位表演者的 `cues`
  与场景级 `handoffs`、`capacityZones`、`travel`（合法时为规整后的参数，缺省时为 `null`）
  已经过同样规整，可直接回传。旧的无 `r`、无 `obstacles`、无 `cues`、无 `handoffs`、
  无 `capacityZones`、无 `travel` 场景数据完全兼容
  （前端实时编辑走本地同一引擎，此接口用于集成/校验）
- `GET /healthz` — 健康检查

### HTTP 调用示例（curl）

携带滚动窗口奔波负荷参数 `travel`（缺省该字段的旧请求保持原有分析行为，返回 `travel: null`）：

```bash
curl -s -X POST http://localhost:3000/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{
    "duration": 10,
    "performers": [
      {"id":"a","name":"甲","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":1000,"y":0}]},
      {"id":"b","name":"乙","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":100,"y":0}]}
    ],
    "travel": { "windowSeconds": 4, "distanceLimit": 200 }
  }'
```

甲 100 单位/秒、乙 10 单位/秒：甲任意 4 s 窗口路程 400 > 200，`travelResults` 中甲
`overloaded: true`、唯一超限起点范围 `{start:0,end:6,maxDistance:400,maxStart:0}`；
乙路程 40 ≤ 200，`ranges` 为空。W 等于总时长时只检查起点 0：

```bash
# 合法：W=duration
curl -s -X POST http://localhost:3000/api/analyze -H 'Content-Type: application/json' \
  -d '{"duration":10,"performers":[
    {"id":"a","name":"甲","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":1000,"y":0}]},
    {"id":"b","name":"乙","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":100,"y":0}]}],
    "travel":{"windowSeconds":10,"distanceLimit":500}}'
# 非法参数：400 且 error 给出清晰说明（不执行分析）
curl -s -X POST http://localhost:3000/api/analyze -H 'Content-Type: application/json' \
  -d '{"duration":10,"performers":[
    {"id":"a","name":"甲","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":1000,"y":0}]},
    {"id":"b","name":"乙","radius":0,"keys":[{"t":0,"x":0,"y":0},{"t":10,"x":100,"y":0}]}],
    "travel":{"windowSeconds":12,"distanceLimit":500}}'
# -> {"error":"滚动窗口时长 windowSeconds 不能超过总时长 10 秒"}
```
